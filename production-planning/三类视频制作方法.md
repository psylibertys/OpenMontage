# 三类视频制作方法

更新：2026-07-24

> 本文记录当前 OpenMontage 与 AutoDL ComfyUI 已具备的三种视频制作方法。新 Agent 必须先读取 `COMFYUI_AGENT_CONTEXT.md` 和 `.agents/skills/comfyui/SKILL.md`，并以代码注册表中的活动 workflow 为准。真正开始制作时仍须按 `AGENT_GUIDE.md` 进入对应 pipeline。

## 一、固定主角不说话，以旁白推进故事

### 适用内容

- 寓言、哲理故事、心灵文案；
- 有固定主角的连载短视频；
- 人物心理活动为主、不需要口型的叙事。

### 制作链路

1. 确定角色外貌、发型、服装、饰品和画面风格。
2. 建立四张角色参考图：正面近景、3/4 侧脸、半身或全身、服装与标志性细节。
3. 使用 `flux2_klein_4ref`，以同一参考包生成不同场景、动作和机位的静帧。
4. 使用 `flux2_klein_inpaint` 修复脸、手、服装或身份漂移。
5. 普通动态使用 `wan22_i2v_q6`；精确动作根据角色类型使用 Animate 或 SCAIL。
6. 使用 Qwen3-TTS 生成旁白。
7. OpenMontage 负责镜头拼接、旁白、字幕、音乐和转场。

### Workflow 选择

- 普通静帧动态化：`wan22_i2v_q6`；
- 写实人物精确动作：`wan22_animate_character`；
- 卡通或非写实人物精确动作：`wan_scail_character`；
- 重点封面与 Hero Frame：显式使用 `krea2_extra_pass`；
- 普通分镜和配图：默认使用 `krea2_low_vram`；
- 重点静帧最终放大：`seedvr2_upscale`。

`wan22_i2v_q6` 通过 `duration_seconds` 选择约 1/2/3/4/5 秒档位。Animate/SCAIL 默认跟随驱动视频时长；可以截短，不能超过源视频，也不会自动循环。

### 质量原则

- 固定身份描述必须在每张分镜中复用；相同 seed 不能替代参考图一致性。
- 无 LoRA 阶段优先固定发型、服装和色彩体系。
- 中近景比远景小脸更容易维持身份。
- 普通动作优先 I2V，只有标志性动作才使用驱动视频。
- 若跨大量作品仍持续漂移，再考虑 Krea LoRA。

## 二、固定主角在不同场景中说话或对话

### 适用内容

- 固定角色口播；
- 故事人物的独白和对话；
- 虚拟主播、角色化栏目和短台词视频。

### 制作链路

1. 使用同一四参考角色包生成每个场景的说话静帧。
2. 按说话人、台词和镜头拆分音频，单句优先控制在 3-6 秒。
3. 使用 Qwen3-TTS 为每句台词生成音频。
4. 将“当前场景图 + 当前台词音频”交给 InfiniteTalk。
5. 穿插倾听反应、环境、物件和无台词动作镜头。
6. OpenMontage 完成对话剪辑、字幕、音乐和成片。

### 配音选择

- `qwen3_tts_custom_voice`：使用预设音色；
- `qwen3_tts_voice_design`：用自然语言设计栏目声线；
- `qwen3_tts_voice_clone_save`：用已授权的 10-20 秒干净录音建立固定声线；
- `qwen3_tts_voice_clone_load`：后续复用固定声线包。

### 口型选择

- `wan_infinitetalk_short`：默认说话镜头，可选约 1.00/2.28/3.56/4.84/6.12 秒；
- `wan_infinitetalk_extend`：只有明确需要长台词时显式选择，不进入随机时长和默认路由。

### 对话剪辑原则

- 说话画面优先使用面部清晰、嘴部无遮挡的胸像或中近景。
- 两人对话分别生成单人说话镜头，再用过肩、倾听反应和环境镜头组接。
- 当前模板不适合在同一个双人画面内精确指定谁在说话。
- 当前活动模板不能同时传入“精确动作驱动视频 + 口型音频”；应拆镜头处理，或后续建设组合 workflow。
- InfiniteTalk 负责当前图片的口型，不替代上游人物一致性。

## 三、产品介绍、广告和带货视频

### 形式一：旁白型产品介绍

使用真实产品照片或视频，结合 AI 使用场景、Qwen3-TTS 旁白、字幕、卖点、价格和 CTA。这是当前最稳定的产品视频路径。

推荐 pipeline：`animated-explainer`，或真实素材较多时使用 `hybrid`。

### 形式二：虚拟主播带货

1. 使用 `flux2_klein_4ref` 维持固定主播形象。
2. 使用 Qwen3-TTS 生成逐句台词。
3. 使用 `wan_infinitetalk_short` 生成主播口播镜头。
4. 穿插真实产品图、细节视频、参数卡片、优惠信息和 CTA。
5. 由 OpenMontage 完成剪辑和信息包装。

推荐 pipeline：`avatar-spokesperson`。

推荐节奏：

```text
主播说一句
→ 产品细节
→ 使用场景
→ 主播补充
→ 参数或优惠卡片
→ 产品定妆图和 CTA
```

### 形式三：氛围型品牌广告

使用 Krea 生成生活方式、环境和情绪画面，Flux 维持人物，Wan I2V 生成轻微动态，OpenMontage 叠加真实产品、Logo、品牌文字、音乐和转场。

推荐 pipeline：`cinematic`。

### 产品资产包

正式制作前应准备：

- 产品透明 PNG；
- 多角度产品照片；
- 产品实拍短视频；
- Logo SVG/PNG；
- 品牌字体和色彩规范；
- 已审核的卖点、参数、价格和优惠信息；
- 禁用表述和合规要求；
- 需要真实演示的使用步骤素材。

### 产品真实性红线

以下内容不应交给生成模型凭空重画：

- 包装文字、Logo、型号、规格和二维码；
- 产品结构、接口、按钮和准确操作步骤；
- 价格、优惠和药品、保健品、金融等合规信息。

这些元素应使用真实产品图或 OpenMontage 图形层叠加。人物准确拿取产品、手指操作按钮、产品 360 度旋转、机械结构演示等，应使用实拍、3D 产品模型或后续专用产品 workflow。

## 共用生产规则

1. OpenMontage 通过 ComfyUI HTTP API 调用 API-format workflow，不依赖浏览器手动点击。
2. 所有正式输出显式写入 `projects/<项目>/assets/`。
3. 视频优先通过 `duration_seconds` 控制长度，不默认生成长镜头。
4. 活跃批次内不逐条删除远端输入、输出和临时文件；相同输入按 SHA-256 复用。
5. 批次结束后先将项目成品备份到 Mac，校验大小和 SHA-256，再只删除不会复用的远端资产。
6. 模型、自定义节点、已批准角色包、声音包和参考素材包属于长期资产，不得误删。
7. 备份、校验、清理和空队列审计全部通过后，由 Agent 主动关闭 AutoDL。

## 当前能力边界

- 无 LoRA 可以达到可用的人物一致性，但不能保证每一帧完全相同。
- 复杂侧脸、快速动作、手部、复杂服装和远景小脸更容易漂移。
- 精确人物与产品交互、双人同画面口型分配、精确动作与口型同时驱动，仍需要实拍、拆镜头或后续专用 workflow。
